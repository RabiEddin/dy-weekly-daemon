Seek: 반복적 탐색으로 놓친 관련 문서를 복구하는 LLM 기반 검색 프레임워크

기존 LLM 기반 검색기와 재순위 지정기는 단일 패스로 말뭉치와 상호 작용하여 한 번 놓친 관련 문서는 영구적으로 복구할 수 없다는 문제가 있다. Seek은 이를 해결하기 위해 테스트 시점에 반복적인 말뭉치 상호 작용을 수행하는 학습 없는 프레임워크다. 각 라운드에서 LLM이 누적된 관련성 피드백을 바탕으로 의사 패시지를 생성하고, 검색기가 새로운 후보를 제시하며, 전담 평가자가 등급별 관련성 판정을 내려 다음 라운드를 안내한다.

핵심 포인트: 핵심 성과: TREC Deep Learning에서 훈련된 재순위 지정기와 동등한 순위 품질을 달성하면서 Recall@100을 일관되게 개선했으며, BRIGHT 벤치마크에서 Qwen2.5-7B 대비 BM25 대비 82% 상대 이득을 달성하고, GPT-4.1로는 평균 nDCG@10 37.4를 기록해 최강 베이스라인을 37% 초과했다.

RAG 파이프라인: 검색 최적화보다 생성 후 검증이 핵심

현대 RAG 파이프라인은 다양한 개선 기능을 포함하지만 이들이 개별적으로만 검증되어 상호작용이 측정되지 않는 문제가 있다. 이 연구는 섹션 확장, 에이전트 검색, 완전성 확인, 목차 기반 검색 등 4가지 기능을 2^4 완전 요인 설계로 768개 조건에서 검증했다. 결과적으로 생성 후 완전성 확인이 가장 강력한 기능(d=+0.48)으로, 이 기능 하나만으로도 다른 3가지 기능 조합보다 우수한 성능(4.31/5 vs 4.11)을 달성하며, 기능의 유용성은 쿼리 유형에 따라 크게 달라진다.

핵심 포인트: 핵심 성과: 완전성 확인 기능이 정확도, 완성도, 유용성을 동시에 향상시키는 최강 성능(d=+0.48, p<0.001)을 입증했으며, 목차 기반 검색은 LLM 비용 없이 유의미한 개선(d=+0.22)을 제공한다. 검색 최적화보다 답변 검증이 더 중요하며, RAG 기능 평가에는 다양한 쿼리 유형의 팩토리얼 설계가 필수적임을 보여준다.

🔗 arxiv.org/abs/2609.35774

RAG 파이프라인: 인도 정부 규제 문서 기반 파서·청킹·임베딩 상호작용 연구

RAG 파이프라인의 구성 요소인 문서 파서, 청킹 전략, 임베딩 모델이 독립적으로 선택되어 실제 평가에서는 이들의 결합 효과가 충분히 검증되지 않는 문제를 다룬다. 본 연구는 3개의 파서, 3개의 청킹 전략, 5개의 임베딩 모델과 BM25 베이스라인을 인도 정부 규제 문서 4개에 대해 800개의 질문 인스턴스로 체계적으로 평가한 팩토리얼 스터디를 제시한다. 선형 혼합 효과 모델과 부트스트랩 신뢰 구간을 통해 54개의 고유한 검색기 구성에 대한 성능을 분석하고, 파서와 청킹 선택이 상당한 상호작용을 보이며 단일 검색기 계열이 모든 문서에서 지배적이지 않음을 발견했다.

핵심 포인트: 핵심 기여: 72,000행의 결과 데이터셋을 통해 MPNet-base의 심각한 실패 모드 발견, 증거 보존율 98% 이상의 포화 천장값 확인으로 검색 차이의 주요 원인이 정보 손실이 아닌 랭킹 품질임을 입증, 800개 질문 벤치마크와 완전한 평가 하네스를 공개 제공.

RRSI — LLM 에이전트 하네스의 자가개선 프레임워크

LLM 에이전트의 성능은 동결된 모델 주변의 프롬프트, 제어 흐름, 도구, 메모리 등 하네스에 의해 결정되지만, 고정 데이터셋에서 하네스를 진화시킬 때 과적합 문제가 발생한다. RRSI는 하네스 편집 공간을 열어두고 탐색 궤적을 정규화하는 방식으로 이를 해결한다. 편집 예산 제한, 노이즈 조정 하한선, 추가 토큰의 실측 이득 기준화, 정체된 컴포넌트 가지치기 등 네 가지 장치로 과적합, 미세 조정 오류, 복잡도 누적을 방지한다.

핵심 포인트: 핵심 기여: 자가개선 루프에 고전 머신러닝 정규화 기법(L0, Lasso, Ridge)을 적용하여 분포 외 일반화 성능 유지. 모델 가중치를 고정하면서 프롬프트, 도구, 메모리, 제어 흐름, 서브에이전트까지 모두 자동 개선 가능.
